[2] บทวิเคราะห์ความซับซ้อนของอัลกอริทึม (BIG-O ANALYSIS)
--------------------------------------------------------------------

1. Algorithm A (Sliding Window / Two-Pointer)
   - Time Complexity: O(N) ถ้าข้อมูลเรียงตามเวลาอยู่แล้ว / O(N log N) กรณีแย่ที่สุด (ข้อมูลไม่เรียง)
     * การอ่านและจัดกลุ่มข้อมูลตาม username ใช้เวลา O(N)
     * ก่อนสแกน จะตรวจสอบก่อนว่าข้อมูลของผู้ใช้แต่ละคนเรียงตามเวลาอยู่แล้วหรือไม่ (O(N))
       - ถ้าเรียงอยู่แล้ว: ข้ามการเรียงลำดับ (Sorting) ไปเลย เหลือเพียงขั้นตอน Sliding
         Window แบบ Two-Pointer ที่ใช้เวลา O(N) รวมทั้งหมดจึงเป็น O(N)
       - ถ้ายังไม่เรียง: ต้องเรียงลำดับ (Sorting) ก่อน ใช้เวลา O(N log N) ซึ่งเป็นขั้นตอน
         ที่ใช้เวลามากที่สุด รวมทั้งหมดจึงเป็น O(N log N)
   - Space Complexity: O(N)
     * ใช้เก็บโครงสร้างข้อมูล dictionary และ list ของเหตุการณ์ login ใน memory

2. Algorithm B (Brute Force)
   - Time Complexity: O(N^2) ไม่ว่าข้อมูลจะเรียงตามเวลาอยู่แล้วหรือไม่
     * มีการวนลูปซ้อนกันเพื่อตรวจสอบทุกคู่อันดับเริ่มต้นและสิ้นสุดของชุดรายการ FAILED
       ซึ่งเป็นขั้นตอนที่ใช้เวลามากที่สุดและเป็นตัวกำหนด Time Complexity โดยรวม
     * เช่นเดียวกับ Algorithm A มีการตรวจสอบก่อนว่าข้อมูลเรียงตามเวลาอยู่แล้วหรือไม่
       (O(N)) และข้ามการเรียงลำดับถ้าไม่จำเป็น แต่การข้าม Sorting นี้เพียงลดเวลาที่ใช้
       จริง (constant factor) เท่านั้น ไม่ได้เปลี่ยน Time Complexity โดยรวม เพราะ O(N^2)
       จากลูปซ้อนยังคงมากกว่า O(N log N) ของการเรียงลำดับเสมอเมื่อ N มีขนาดใหญ่
     * เมื่อปริมาณ log (N) เพิ่มขึ้น เวลาในการประมวลผลจะพุ่งสูงขึ้นเป็นแบบกำลังสอง
   - Space Complexity: O(N)
     * ใช้พื้นที่หน่วยความจำในการเก็บข้อมูลเท่ากับ Algorithm A


[3] ข้อสรุปเพื่อนำไปเขียนรายงานและสไลด์นำเสนอ (SUMMARY)
--------------------------------------------------------------------
จากผลการทดสอบจริงพบว่า Algorithm A (Sliding Window) ใช้เวลาในการประมวลผล
น้อยกว่าและปรับขนาดได้ดีกว่า Algorithm B (Brute Force) เมื่อจำนวนข้อมูลเพิ่มขึ้น
เนื่องจากมี Time Complexity เป็น O(N) เมื่อ log เรียงตามเวลาอยู่แล้ว หรือ O(N log N)
กรณีแย่ที่สุด เทียบกับ Algorithm B ที่ยังคงเป็น O(N^2) เสมอไม่ว่าข้อมูลจะเรียงลำดับ
มาก่อนหรือไม่ ทำให้ Algorithm A เหมาะสำหรับการรองรับระบบตรวจจับ Log ขนาดใหญ่
ในระดับการใช้งานจริง (Scalability) โดยเฉพาะเมื่อ Log ที่รับเข้ามาเรียงตามเวลาอยู่แล้ว
ซึ่งเป็นกรณีที่พบได้บ่อยในระบบจริง (เช่น Log ที่ไหลเข้ามาตามลำดับเวลาเกิดเหตุการณ์)
